
# Product Requirements Prompt (PRP) — 🔘 Pending

## 1. Project Context & Objectives

The system requires an advanced mathematical transformation engine to allow the user to navigate the Tonnetz grid using an 8-way directional controller. The engine must adhere strictly to a Universal Pitch-Class Set Navigation Geometry, ensuring that complex pitch-class sets maintain their intervallic integrity and geometric orientation without drift.

## 2. Technical Decisions & Dependencies

* **Immutable Blueprint Architecture:** The system must track transformations via an immutable Base Blueprint ($I$), a tracking Current Root ($r$), and a Polarity State ($F$). It must **never** calculate the next state recursively from the current active output notes.
* **Safe Modulo Arithmetic:** JavaScript's native modulo operator (`%`) mishandles negative numbers. All modulo 12 operations must use a safe helper function: `const mod12 = (n) => ((n % 12) + 12) % 12;`.
* **Operations:**
* **Operation A (Keep/Translate):** 
$$S_{active} = (r + I) \pmod{12}$$


* **Operation B (Flip/Invert):** 
$$S_{active} = (r - I + 7) \pmod{12}$$





## 3. Implementation Phases

### Phase 1: Engine State & Initialization — 🔘 Pending

* **Objective:** Establish the foundational state variables and the "Parse Input" logic to capture a user's pitch-class set as the Base Blueprint.
* **Instructions:**
1. Create a new custom hook (e.g., `useTonnetzTransform.ts`) or module to encapsulate this logic.
2. Define the state interface: `{ I: number[], r: number, F: 0 | 1 }`.
3. Implement an initialization function: `initTransformState(activePitchClasses: Set<number>)`.
* Sort the set ascending. Select the lowest integer as $r$.
* Map the set to generate the blueprint $I$: `I = Array.from(activePitchClasses).map(note => mod12(note - r))`.
* Set $F = 0$.

* **Test Case 2:** [Given an inversion (4, 7, 0), When initialized, Assert it sorts to (0, 4, 7) yielding the same blueprint].

### Phase 2: Core Matrix Operations — 🔘 Pending

* **Objective:** Implement the transformation operators and the state transition matrices.
* **Instructions:**
1. Implement the lookup tables for Matrix 1 ($F = 0$) and Matrix 2 ($F = 1$) containing the `delta_r` and `F_new` target for all 8 directions.
2. Implement `handleDirectionalTrigger(direction)`.
* Read current $F$ to select the correct matrix.
* Extract $\Delta r$ and $F_{new}$ based on the directional input.
* Update state: $r_{new} = (r + \Delta r) \pmod{12}$, update $F = F_{new}$.


3. Implement the output renderer:
* If $F_{new} == 0$, calculate output via Operation A for each integer in $I$.
* If $F_{new} == 1$, calculate output via Operation B for each integer in $I$.
* Return the resulting mapped array of integers.




* **TDD Checkpoint:** * **Test Case 1 (Matrix 1):** [Given $I=[0,4,7]$, $r=0$, $F=0$ (C Major), When direction is RIGHT, Assert $r_{new}=4$, $F_{new}=1$, and output is (4, 11, 7) or E Minor].
* **Test Case 2 (Matrix 2):** [Given previous state $r=4$, $F=1$ (E Minor), When direction is UP, Assert $r_{new}=4$, $F_{new}=0$, and output is (4, 8, 11) or E Major].
* **Status Update:** "Transition Phase status to 🔵 Active. Author and run tests. Update status to ✅ Completed before proceeding."
