# Product Requirements Prompt (PRP) — Context Menu Bugfix ✅

## 1. Project Context & Objectives
The recent layout updates successfully positioned and scaled the Navigation widget. However, the CSS `transform` properties (`scale` and `translate`) on the parent wrapper have created a new containing block. This breaks the `position: fixed` behavior of the Context Menus, causing them to render off-screen because their `top` and `left` inline styles (derived from `e.clientY` and `e.clientX`) are now being calculated relative to the transformed wrapper instead of the viewport. The objective is to use React Portals to render the context menus at the document root, escaping the transformed stacking context.

## 2. Technical Decisions & Dependencies
* **Target File:** `/components/navigation/NavContainer.tsx`
* **Strategy:** Import `createPortal` from `react-dom`. Wrap the conditional renders for `ArrowContextMenu` and `GlobalContextMenu` inside `createPortal(..., document.body)`. This attaches them directly to the DOM root, restoring normal `position: fixed` behavior.

## 3. Implementation Phases

### Phase 1: Implement React Portals — ✅ Completed
* **Objective:** Escape the transformed parent wrapper for the context menus.
* **Instructions:**
  1. Open `NavContainer.tsx`.
  2. Add the import: `import { createPortal } from 'react-dom';`
  3. Locate the rendering block at the bottom of the component for the Context Menus.
  4. Wrap the `ArrowContextMenu` inside a portal:
     ```tsx
     {contextMenu?.type === 'BUTTON' && createPortal(
       <ArrowContextMenu 
         buttonId={contextMenu.buttonId}
         config={configs[contextMenu.buttonId]}
         onUpdateConfig={updateButtonConfig}
         position={{ x: contextMenu.x, y: contextMenu.y }}
         onClose={closeContextMenu}
       />,
       document.body
     )}
     ```
  5. Repeat the exact same `createPortal(..., document.body)` wrapping for the `GlobalContextMenu`.
