# Product Requirements Prompt (PRP) — UI Bug Fixes ✅

## 1. Project Context & Objectives
The previous layout adjustments failed to properly align the Navigation widget's bottom margin with the adjacent UI cards. Furthermore, the "Learn Mode" popup is occluding the Navigation widget because it is hardcoded to render at the bottom of the screen, and the Context Menus are rendering too close to the viewport edge. The objective of this phase is to strictly enforce horizontal margin alignment, move the Learn Mode banner to the top of the screen, and increase the viewport boundary padding for the context menus.

## 2. Technical Decisions & Dependencies
* **Target Files:**
  * `components/navigation/NavContainer.tsx` (For popup positioning and menu padding).
  * The parent wrapper component in `App.tsx` or `TonnetzGridContainer.tsx` (For layout classes).
* **Styling Adjustments:**
  * **Learn Mode Banner:** Reposition from `fixed bottom-8` to `fixed top-16` (or similar top-anchor) so it acts as a global header banner instead of an overlapping tooltip.
  * **Context Menu Padding:** Increase the boundary padding variable from `16px` to `64px` to ensure menus sit comfortably inside the viewport.
  * **Bottom Margin Alignment:** The AI developer must inspect the adjacent left/right data cards, identify their exact `bottom-*` spacing class, and apply that *exact* class to the Navigation widget wrapper, ensuring `origin-bottom` is applied alongside the `scale` transform to eliminate phantom gaps.
  * **Status Reconciliation:** Verify all sub-phases match ✅ before updating top-level status to ✅.
  * **Final Sign-off:** Present the running application to the user for layout approval.

## 3. Implementation Phases

### Phase 1: Learn Mode Banner Repositioning — ✅ Completed
* **Objective:** Move the "Learn Mode Active" overlay so it does not block the Navigation UI.
* **Instructions:**
  1. Open `NavContainer.tsx`.
  2. Locate the JSX for the Learn Mode overlay (currently containing `fixed bottom-8 left-1/2 -translate-x-1/2...`).
  3. Change the vertical positioning classes to anchor it to the top of the screen (e.g., replace `bottom-8` with `top-16` or `top-12`).
* **TDD Checkpoint:** * **Test Case 1:** [Given the app is running, When the user starts Learn Mode, Assert the black "LEARN MODE ACTIVE" banner appears at the top center of the screen, leaving the Navigation D-pad completely visible.]
    * **Status Update:** "Transition Phase status to 🔵 Active. Apply the class changes. Once verified, update status to ✅ Completed."

### Phase 2: Context Menu Boundary Padding — ✅ Completed
* **Objective:** Ensure Context Menus have comfortable breathing room from the edge of the browser window.
* **Instructions:**
  1. Open `NavContainer.tsx`.
  2. Locate the boundary detection math in `handleButtonContextMenu` and `handleBackgroundContextMenu`.
  3. Update the padding constant: `const padding = 64;` (or add/increase the padding value in the clamp equation).
* **TDD Checkpoint:** * **Test Case 1:** [Given the app is running, When the user right-clicks the 'DOWN' arrow, Assert the Context Menu renders with at least ~64px of space between its bottom edge and the bottom of the browser viewport.]
    * **Status Update:** "Transition Phase status to 🔵 Active. Adjust the padding constant. Once verified, update status to ✅ Completed."

### Phase 3: Strict Margin Reconciliation — ✅ Completed
* **Objective:** Perfectly align the bottom edge of the Navigation widget with the existing left/right peripheral cards.
* **Instructions:**
  1. Inspect the main UI layout file (`App.tsx` or equivalent) to find the Tailwind classes for the bottom-left and bottom-right info cards. Note their exact bottom spacing (e.g., `bottom-6` or `mb-6`).
  2. Apply that exact same spacing class to the absolute/fixed wrapper `div` of `<NavContainer />`.
  3. **CRITICAL:** Ensure the wrapper has the `origin-bottom` class applied alongside the `scale` class. If `origin-bottom` is missing, the scale transform will shrink the widget towards its center, creating a massive unwanted gap at the bottom.
* **TDD Checkpoint:** * **Test Case 1:** [Given the app is running, When the user looks at the bottom of the screen, Assert a straight horizontal line could be drawn across the bottom edge of the left card, the Navigation widget, and the right card.]
    * **Status Update:** "Transition Phase status to 🔵 Active. Audit the adjacent cards and apply the exact matching classes. Once verified, update status to ✅ Completed."
    * **User Verification:** "[USER VERIFICATION REQUIRED] Pause for user review. Confirm the bottom margin is finally correct, the Learn Mode banner is at the top, and context menus no longer crowd the edge."
