# Product Requirements Prompt (PRP) — ✅ Completed

## 1. Project Context & Objectives
The Navigation widget's context menus are successfully rendering via React Portals, but they are clipping out of the bottom of the viewport when triggered on lower UI elements. Additionally, the widget is still floating too high above the bottom edge of the screen, failing to align with the bottom margin of the adjacent data cards. The objectives of this phase are to implement dynamic boundary detection for the context menu coordinates and aggressively lower the Navigation widget's anchor point.

## 2. Technical Decisions & Dependencies
* **Target Files:**
  * `components/navigation/NavContainer.tsx` (For menu coordinate logic).
  * The parent wrapper component in `App.tsx` or `TonnetzGridContainer.tsx` (For layout classes).
* **Boundary Detection Logic:** Implement a constraint algorithm before setting the `contextMenu` state. We will assume a maximum context menu size (e.g., `260px` width, `220px` height) and clamp the `e.clientX` and `e.clientY` values against `window.innerWidth` and `window.innerHeight` with a `16px` safety padding.

## 3. Implementation Phases

### Phase 1: Context Menu Boundary Detection — ✅ Completed
* **Objective:** Prevent context menus from rendering outside the visible browser window.
* **Instructions:**
  1. Open `NavContainer.tsx`.
  2. Locate the `handleButtonContextMenu` and `handleBackgroundContextMenu` functions.
  3. Implement the following boundary logic in *both* handlers before calling `setContextMenu`:
     ```javascript
     const MENU_WIDTH = 260; // Estimated max width
     const MENU_HEIGHT = 220; // Estimated max height
     const padding = 16;
     
     let adjustedX = e.clientX;
     let adjustedY = e.clientY;
     
     if (adjustedX + MENU_WIDTH > window.innerWidth) {
       adjustedX = window.innerWidth - MENU_WIDTH - padding;
     }
     if (adjustedY + MENU_HEIGHT > window.innerHeight) {
       adjustedY = window.innerHeight - MENU_HEIGHT - padding;
     }
     ```
  4. Pass `adjustedX` and `adjustedY` into the state instead of raw `e.clientX` / `e.clientY`.
* **TDD Checkpoint:** * **Test Case 1:** [Given the app is running, When the user right-clicks the very bottom 'DOWN' arrow, Assert the ArrowContextMenu renders fully visible above the bottom edge of the browser.]
    * **Status Update:** "Transition Phase status to 🔵 Active. Apply the coordinate math. Once verified, update status to ✅ Completed."

### Phase 2: Aggressive Layout Anchoring — ✅ Completed
* **Objective:** Force the widget downward to match the bottom margins of the peripheral UI cards.
* **Instructions:**
  1. Locate the absolute/fixed container `div` wrapping `<NavContainer />`.
  2. Change the bottom spacing class from `bottom-4` to `bottom-0`. If the `scale` transform is still leaving phantom space, use a negative bottom margin (e.g., `-bottom-2` or `-bottom-4`) until the visual margin matches the adjacent cards.
  3. Ensure `origin-bottom` is explicitly set so the scale transformation anchors downward.
* **TDD Checkpoint:** * **Test Case 1:** [Given the app is running, When viewing the bottom of the screen, Assert the bottom edge of the Navigation widget sits flush with the horizontal alignment of the bottom-left and bottom-right info cards.]
