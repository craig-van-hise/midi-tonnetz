# Product Requirements Prompt (PRP) — ✅ Completed

## 1. Project Context & Objectives
The 7th Chord State Engine currently suffers from a "stale state" bug. Unsupported 4-note sets (e.g., Dominant 7th, Half-Diminished) fail the Maj7/Min7 validation in `initTransformState`, leaving `seventhState` untouched. However, downstream functions (`getOutputNotes` and `handleDirectionalTrigger`) blindly intercept *all* arrays where `length === 4`, forcing the visualizer to render the previously cached 7th chord. The objective is to implement an `isActive` flag so unsupported 4-note chords gracefully fall back to the Triad geometric engine.

## 2. Technical Decisions & Dependencies
* **Explicit Validity Tracking:** `seventhState` must be expanded to track a boolean `isActive` flag.
* **Safe Intercepts:** `getOutputNotes` and `handleDirectionalTrigger` must intercept based on `seventhState.isActive` rather than purely `I.length === 4`.

## 3. Implementation Phases

### Phase 1: State Validity Flag Initialization — ✅ Completed
* **Objective:** Expand the `seventhState` to explicitly track if a valid Maj7/Min7 shape is currently active.
* **Instructions:**
    1. In `useTonnetzTransform.ts`, update the `seventhState` initialization to include `seventhIsActive: false`.
    2. Inside `initTransformState`, before the `for (const rootCandidate of arr)` loop, declare a local tracking variable: `let foundValid7th = false;`.
    3. If a Maj7 or Min7 match is found, set `foundValid7th = true`, call `setSeventhState({ ..., seventhIsActive: true })`, and `break`.
    4. *Crucial:* After the loop finishes, if `!foundValid7th`, strictly call `setSeventhState({ seventhRoot: 0, seventhIsFlipped: false, seventhIsActive: false })` to wipe any stale data.
