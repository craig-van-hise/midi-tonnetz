# Product Requirements Prompt (PRP) — 🔘 Pending

## 1. Project Context & Objectives
The current rigid geometric transformation engine fails when handling asymmetrical 4-note sets (like 7th chords) due to voice-leading requirements. To resolve "zig-zag" routing errors (e.g., Emaj7 -> Dbmaj7 instead of a clean chromatic slide), the engine must implement a secondary, hardcoded state-machine routing layer specifically for 7th chords.

## 2. Technical Decisions & Dependencies
* **Engine Bifurcation:** The existing geometric engine will remain intact for triads. A new logic block (e.g., `handleSeventhChordTrigger`) must be created to intercept transformations when the active set contains 4 notes.
* **State Tracking:** The 7th chord engine requires tracking two exact variables:
  1. `currentRoot`: Integer (0-11).
  2. `isFlipped`: Boolean (false = Major 7th, true = Minor 7th).
* **Output Generation:** * If `isFlipped === false`, output array is `[R, (R+4)%12, (R+7)%12, (R+11)%12]`.
  * If `isFlipped === true`, output array is `[R, (R+3)%12, (R+7)%12, (R+10)%12]`.
* **Safe Modulo:** All additions must use `((n % 12) + 12) % 12`.
